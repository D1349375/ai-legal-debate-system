# 律師工作台整理(ui-lawyer-cleanup)

目標：v2 案件打開後，律師一眼看到進度、下一步、爭點強弱、書狀、未通過的引用；技術資訊收合到次要位置，不刪除。
盤點用 1440×900、三件 v2 案件(gcis、e2e、construction)逐分頁整頁截圖。整頁高度以 gcis 為例，括號為 before → after(px)。

## 問題 → 改法 → 結果

| 分頁 | 問題 | 改法 | 結果 |
|---|---|---|---|
| 案件總覽 | 一頁攤開約 15 張卡：來源橫幅、進度、即時執行紀錄(token、花費、stream 路徑)、當事人、事實全文、聲明、證據、缺口、統計；進度在右側欄又列一次 | 頂端新增「目前狀態」五行摘要(進度、下一步、爭點強弱、書狀、引用，各附跳轉鈕)；案件輸入收進「案件輸入」摺疊；來源橫幅、已跑完的即時執行紀錄收進「技術細節」；未執行、執行中或可續跑時，執行控制仍在前面 | 2418 → 1047 |
| 右側欄 | 流程進度與總覽重複；資料來源、即時執行、限制三段常駐 | v2 總覽不再顯示右側進度；資料來源／即時執行／限制併入一個摺疊「技術細節」，只留一句免責聲明 | 常駐內容減半 |
| 起訴狀／答辯狀 | 正文前先有 4 張卡(版本橫幅、當事人資料、系統備註、長說明)，要捲動才看到書狀 | 正文緊接在版本列、關卡 1、編輯／匯出鈕之後；版本來源、當事人資料、系統備註收進「版本來源與系統備註」；引用先列未通過者，已通過的收合；說明縮成一句，全文放「完整說明」；關卡 1 按鈕說明縮短 | 起訴狀 5083 → 3268，正文在第一屏 |
| 診斷與 v2 | 一開始是兩大段評估結論／理由長文，爭點強弱表在第 3 屏 | 先「重點」(強中弱計數、待補證據數、修改建議數)，再爭點強弱表(▲強／●中／▼弱，圖示＋文字)、待補證據、修改建議、評估結論；評估理由全文、轉述核對、讓步條件、錨點一致性收進「完整評估理由與技術備註」 | 11803 → 8664；強弱表在第一屏 |
| 書狀交換 | 重複的「AI 模擬」橫幅與說明；階段間引用變化攤開一大片標籤 | 警語併入標題下一句；引用變化收進「技術細節」 | 版面只剩書狀與論證摺疊 |
| 爭點整理表／答辯狀 | 標題下長說明 | 一句＋「完整說明」 | 少兩三行 |
| 引用查證 | 每條都顯示「待查證」，四個統計格全是「—」，像全部沒查過 | 未按查證前，狀態與統計用資料庫先前紀錄(標明「先前紀錄」)；說明縮成一句 | 33/34 先前通過一眼可見 |

## 刻意保留
- 舊流程(非 v2)案件的總覽、右側欄、各分頁行為不變，只共用「完整說明」與右側欄技術細節摺疊。
- 所有按鈕與 API 呼叫不變；顏色只用既有 CSS 變數；狀態一律圖示＋文字。
