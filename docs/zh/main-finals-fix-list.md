**位置**:`engine/verify.py:134-170` `_fjud_search`。

**現況與證據(2026-11-01 實測)**:
- 搜尋「105年度台簡上字第33號」共 50 筆,分 3 頁(每頁 20 筆)。目標在第 3 頁,JID 是 `TPSV,105,台簡上,33,20161026`。
- 程式只讀第一頁,所以回報 `not_found`。這筆判決**不是捏造**。
- 下一頁連結在 `id="hlNext"` 的 `href`,格式 `/FJUD/qryresultlst.aspx?q=<token>&sort=DS&page=2`。
- 加 `&sort=LG`(法院層級大到小)時,這筆會出現在第 1 頁。

**改法**:
1. 取得 token 後,用同一個 opener 讀 `qryresultlst.aspx?q=<token>&sort=LG`,讓最高法院排在前面。實作時確認這個請求要帶的 Referer。
2. 逐頁讀 `hlNext`,每頁間隔 1.5 秒(沿用現有延遲)。找到符合 `_jid_matches` 的 JID 就停止。
3. 頁數設上限(建議 10 頁)。**到上限還沒看完時不可回 `not_found`**,要回 `verification_failed`,並在 `note` 寫明沒有查完。沒查完不等於查無。
4. 沒有 result token 目前一律當成沒有結果。不存在的字號確實沒有 token(`105年度台上字第99999號` 實測如此),但頁面異常也會走到這裡。至少檢查首頁的 `__VIEWSTATE` 取得成功,取不到就回 `verification_failed`。

### 法官一直被 M12 擋時的修正流程

**判定一直被擋**:同一份輸出 3 次都沒過,或一次實跑中訊問與評估合計被退回超過 4 次。後者是我們訂的工程門檻,不是量測結果。實跑停下後,已落地的不會消失,修好可從被擋的那一步續跑。

**先分類,再動手**。報錯原文都會在最後回覆裡。逐句判斷法官寫得對不對:

| 情況 | 代表什麼 | 修法 | 要重跑模型嗎 |
|---|---|---|---|
| 句子真的把假設或資料缺口寫成承認 | **檢查是對的,問題在法官** | 走下面第 1 級 | 要,從被擋的步驟續跑 |
| 「沒有緊接引述」,但法官講的是真實陳述 | 法官用了這些詞卻沒引述 | 走下面第 1 級 | 要,從被擋的步驟續跑 |
| 「引述不在該方論證」,但原句其實存在 | 比對太嚴,例如省略號、改了標點、跨句 | 走下面第 2 級 | 先不用,用報錯句子當測試 |
| 「原句是假設、自我評估」,但原句是事實陳述 | 關鍵字太廣,例如整句其他地方有「不利」 | 走下面第 2 級 | 先不用,用報錯句子當測試 |

**依序升級,每次只改一級**:

1. **改範本**:法官範本明寫「預設不要用這四個詞,寫『被告主張』,需要時才引述原句」,並附一個正例和一個反例。改完從被擋的步驟續跑一次。
2. **放寬比對**:只改 `engine/admission_check.py`。比對先移除省略號;假設與自評的關鍵字只看引述到的那個分句,不看整句。每個誤擋句子都先變成會失敗的測試。**以下固定反例必須仍被擋**:`被告已自認沒有行車紀錄器`、`被告自承「這是本案最大弱點」`、`被告自認「行車紀錄器資料未載」`,以及句中有別的引述但自承後面是作者轉述的句型。
3. **評估改成警告,訊問維持硬擋**:`main.py verdict` 與 `check-judge` 對評估改成警告,讓評估落地,UI 在評估頁頂端列出未通過的句子。理由是評估被卡住整案就沒有結論,而訊問錯了會往後傳,必須擋。
4. **全部改成警告**:訊問也只警告,UI 同樣列出。這時台上**不能**說「程式擋下」,只能說「程式標示,由律師判斷」。

**時間界線**:第 3、4 級只有在 11/4 中午前第 1、2 級都試過還是過不了時才用。11/4 晚上還沒有一次完整實跑,第二批不併,第一批照併。

**不能做的事**:不要為了過關刪掉法官的訊問或內容;不要讓主 agent 代改法官的句子;不要手改 JSON 後說是模型產出;不要把這四個詞之外的字樣加進硬擋,換詞的問題交給人工抽查(V35)。

**額度**:實跑一次約 15 分鐘、估算 3.25 美元(#4 的數字)。續跑只跑剩下的步驟,所以第 1 級優先用續跑;第 2 級用報錯句子跑測試,不花額度。
