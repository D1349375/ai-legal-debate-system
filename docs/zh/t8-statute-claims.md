## 1. 做了什麼

`python main.py statute-claims --json <檔>`:讀評估、書狀或訊問的 JSON(不是 JSON 就當純文字，例如書狀正文),印出

```json
{"claims": [{"citation": "公司法第23條第3項", "law_name": "公司法", "articles": ["23"],
             "description": "公司對負責人訴訟之代表人", "form": "括號說明",
             "where": ["questions[1].question_text"]}]}
```

- `articles` 是給 `python main.py article <law_name> <條號>` 用的條號(子條文寫成 `191-2`,和 `article` 相同)。連寫的條號(「第277條前段、第278條第1項」)全部列出。
- `where` 是 JSON 路徑，純文字為「全文」。同一引用與描述出現在多處只列一次。
- 沒有描述的引用不列出。不判斷描述對不對，判斷交給查證 subagent。

認得的寫法(`engine/statute_claims.py`):

| `form` | 例子 | 描述取哪裡 |
|---|---|---|
| 括號說明 | 公司法第23條第3項(公司對負責人訴訟之代表人) | 括號內。證據編號、「下稱」、「見」、「參照」、純日期數字不算 |
| 條文後引號 | 民法第356條第2項但書『依通常之檢查不能發見之瑕疵』、公司法第23條第1項所稱「損害」 | 引號內容 |
| 依條文規定轉述 | 依民法第184條第1項前段規定，因故意或過失… | 「規定」之後到句末;引號則到右引號 |
| 前文轉述後稱定有明文 | 按當事人主張…之責任，民事訴訟法第277條前段定有明文 | 同一句引用之前的文字，去掉「按」等開頭 |
| 括號引用前的說明 | 被告得主張損益相抵(民法第216條之1) | 括號裡只有條文時，括號前到上一個標點，最多 60 字 |

法規名稱沿用 `engine/verify.py` 的 `STATUTE_CITATION_RE`(名稱索引裡的才認),只 import,沒改。

## 2. 找引用的做法與理由

任務文件讓我們在「查證 subagent 自己從文字找」與「新增純函數指令」之間選一個。選新增指令：

- 查證 subagent 自己找，範圍和漏掉多少都看模型當次怎麼讀，沒辦法測。指令可以用測試固定，漏掉的寫法補一條規則就好。
- 只抽取不判斷，符合「結構可以硬擋，自然語言只警告」:這個指令不擋任何東西，只決定查證 subagent 要讀哪幾條。
- 成本可預估：先知道要跑幾次 `article`(7 天內讀快取)。

- 每件約 5–6 則，就是查證 subagent 每件要多跑的 `article` 次數上限(同條文會讀快取)。
- 有幾則不是條文內容的描述，只是段落標題，例如「被保全債權成立時點(民法第244條)」「第一層為過失責任是否成立(民法第184條第1項前段、第191條之2)」。查證 subagent 讀條文後會判為不是內容描述;這是多列的成本，不是漏抓。
- 抓到的「民事訴訟法第277條」那則描述是「我方承認這四項原則上由原告負舉證責任」,是一方對舉證責任的說法，不是條文內容;同樣交給查證 subagent。
