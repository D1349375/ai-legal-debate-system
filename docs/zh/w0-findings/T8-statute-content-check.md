# T8 Step 8 核對條文內容(F6)

- **分支 / 工作目錄**:`pleading-exchange` / `.claude/worktrees/pleading-exchange`
- **做的人**:Codex 改 SKILL 與(必要時)小型輔助指令;Claude 實跑驗證(C2)。前提:T7 已完成。
- **調研**:[README 第 2 節 F6](README.md#f6-法官照一方說法轉述了錯誤的條文內容)

## 問題

W0 訊問 2 寫「公司法第23條第3項(公司對負責人訴訟之代表人)」,但該項是歸入權規定。`verify` 只確認條文存在,所以這條是 `published`。SKILL Step 8 的實質核對只要求讀**判例**全文,沒要求核對**條文內容**和引用處的描述是否一致。

`pleading-exchange` 有 `python main.py article`(依法規名稱與條號查現行條文,7 天內讀快取),可以拿來核對。

## 要做的

1. **SKILL Step 8 第二項任務擴大到條文**:對最終會用進評估(`citations_used`)或書狀的條文引用,若引用處**附有內容描述**(括號說明,或「依某條規定,…」這類轉述),查證 subagent 要用 `python main.py article <法規名稱> <條號>` 讀條文,核對描述與條文是否相符。
   - 不符:視同實質核對失敗,照 Step 8 現有失敗流程(交回提出該引用的 subagent 修正,不得自己改寫)。
   - `article` 查不到或連線失敗:標「無法核對」,照實列入 Step 10,不放行也不當成失敗。依現有狀態名(`network_error`、`unsupported_law` 等)處理,不要自創。
   - 範圍和判例一樣,**只核對最終會用到的**,不擴及 Stage 1–3 的候選。
2. **找出要核對的引用**:先評估由查證 subagent 自己從文字找,還是新增一個純函數指令(例如 `python main.py statute-claims --json <評估或書狀>`,列出「條文 + 附近的描述文字」)。若新增:
   - 放在我們維護的檔(例如新的 `engine/statute_claims.py`),**不要改 `engine/verify.py`、`law_lookup.py` 等組員的檔**。
   - 只抽取、不判斷;判斷交給查證 subagent。
   - 先寫測試,用 W0 訊問 2 的句子當案例。
   - 兩個做法選一個,理由寫進紀錄。
3. **法官訊問**:訊問在 Step 3 落地,不經 Step 8。這項**不改**訊問流程;W0 的例子是原告在 Stage 2 糾正,對抗本身有效。只在 SKILL 的法官訊問指示加一句:轉述一方對條文內容的說法時,要寫成「被告主張第X條規定…」,不要寫成法官自己的描述。這句會影響範本,一起在 C2 驗。
4. 不要在 SKILL 或範本裡寫「正確條號」當例子。公司對負責人訴訟的代表人規定要查證後由律師或組員確認。

## 測試

- 若新增指令:抽取 W0 訊問 2 的句子能得到 `公司法第23條第3項` 與描述「公司對負責人訴訟之代表人」;沒有描述的引用不列出。
- 離線全套測試通過數 = 基準 + 新增數。
- SKILL 改動無法用離線測試驗,寫進 C2 的檢查。

## 完成定義

- SKILL diff 清楚、只動 Step 8(與第 3 點的一句);若有新指令,測試全過。
- 實作紀錄寫出 SKILL 改動前後對照。
