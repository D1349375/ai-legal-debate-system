## 問題

W0 的 6 份論證都有成對的 `【內部檢討】` 段落,但段落外仍有自我評估,`main.py record` 沒警告:

- 被告 Stage 3:「…A1 的力道會減弱,此為內部風險,不是承認。」
- 原告 Stage 2:「…原告承認有疑義,故此一路徑列為最弱備位。」

`engine/internal_review.py` 的 `_SELF_REVIEW_RE` 只有 `弱點|最大風險|最大缺口|對我方不利|對本方不利|我方不利|本方不利|基礎薄弱|自我檢討`。

另外,這些警告只印在 stderr,主 agent 依 SKILL 列進最後回報;UI 看不到次數。

## 要做的

1. **量測**(工具放暫存資料夾):把現有所有論證(示範資料、W0 資料庫複本;實跑 #1–#4 的資料庫要先問使用者)濾掉段落後的公開文字,用新舊詞表各跑一次,列出新增命中的句子。
2. **補 `_SELF_REVIEW_RE`**:候選 `內部風險`、`力道會減弱`、`力道減弱`、`承認有疑義`、`我方承認`、`本方承認`。**不要加單獨的 `最弱`、`備位`、`風險`**:「列為備位」是正當訴訟策略,「風險」在法律論述常用。依量測調整。
3. **讓 UI 看得到**:即時執行時,把每則論證落地時的內部檢討警告數記進執行紀錄,UI 的執行摘要顯示「公開論證疑似含自我檢討:N 則」。
   - 先查 `server/live_run.py` 怎麼記分類器中止(`live_runs.notes_json`),沿用同一個管道,不新增資料表。
   - 若 stream-json 拿不到 `record` 的 stderr,改在 UI 讀取案件時用 `review_warnings` 對已落地論證重算(決定性函數,結果一樣),在攻防分頁的該則論證旁顯示。兩種做法選一個,理由寫進紀錄。
4. SKILL 的說明不改(仍是只警告、列入 Step 10)。

不要做:不改成硬擋;不改 stage 範本;不新增 JSON 欄位。
