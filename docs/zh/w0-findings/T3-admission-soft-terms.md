## 問題

W0 訊問 3 寫「你方 Stage 1 自陳這一點「證據不明,需查證」」。原句所在的句子是「…尚待證明,標示為「證據不明,需查證」。」,這是資料缺口,依 M12 不能稱「自陳」。`engine/admission_check.py` 的 `_SOFT_RE` 有 `待查`,沒有 `待證`、`證據不明`、`需查證`,所以 `check-judge` 放行。

附帶:`templates/verdict_prompt.txt` 第 13 行禁止寫「承認」,但 `ADMISSION_RE` 只認 `自承|自認|自陳|坦承`。

## 要做的

1. **建量測工具**(放暫存資料夾,不進 git):把現有所有紀錄的法官訊問與評估、雙方論證,用**修改前**與**修改後**的 `admission_problems` 各跑一次,列出結果不同的句子。資料來源:
   - `demo/recorded_cases.json`(進 git 的示範資料)。
   - `database/legal_debate.db`(W0 第 2 次,唯讀;**先複製到暫存位置再讀**)。
   - 若使用者同意,`.claude/worktrees/ui-live-run-0f7cc8/database/legal_debate.db`(實跑 #1–#4,同樣複製後再讀)。這顆是另一個 worktree 的,讀之前先問使用者。
2. **補 `_SOFT_RE`**:至少加 `待證`、`證據不明`、`需查證`、`有待查證`。其他候選(例如 `不詳`、`無從確認`、`未能確認`)看量測結果決定。**不要加單字「不明」**(「去向不明」這類是事實陳述)。
3. **`承認` 要不要納入 `ADMISSION_RE`**:用量測工具看加入後法官訊問與評估會新增多少問題、是不是真的有問題。量測後在實作紀錄寫建議,**先不改**,交給 Claude 檢核時一起決定。注意 `承認` 常出現在「不承認」「否認」語境,`_NEGATED_RE` 能不能處理要看量測。
4. 模組 docstring 補一句說明這次加的詞與原因。

不要做:不改 `_QUOTED_RE`、`_NEGATED_RE` 等其他規則;不改法官範本(範本改動要 Claude 實跑,這項不需要)。
