# 全角色 AI 模擬法庭系統（AI Moot Court Simulator）
## 產品功能擴充與技術流程規劃報告

> **報告日期**：2026-08-06  
> **擴充模組**：LegalDebate AI — 旗艦亮點功能「全角色法庭預演與心證分析模組」  
> **定位**：開庭前的戰略級模擬引擎，提供原告、被告、檢察官與法官多方攻防對抗，並產出【事前模擬判決書】與【心證風險分析】。

---

## 一、功能概述與願景

在真實法律實務中，頂級律師事務所為應對重大的刑事訴訟或高額民事糾紛，會在開庭前舉辦昂貴的「模擬法庭（Moot Court）」。

本擴充模組將 DebateSystem 的多 Agent 辯論架構升級為 **「全角色 AI 模擬法庭系統」**。系統能自動根據案件類型（民事或刑事），調度具備專業領域 Skill 的多個 AI 角色，依照標準訴訟法程序進行真實感極高的法庭攻防對抗，並最終由法官 Agent 發布【模擬判決書】與【法官心證形成分析】。

---

## 二、雙訴訟模式架構（Civil vs Criminal Modes）

系統能根據用戶上傳之卷宗與起訴/答辯資料，自動切換對應之法庭角色設定：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 🏛️ 民事訴訟模式 (Civil Courtroom Simulator)                             │
│                                                                        │
│ • 原告訴訟代理人 Agent  ：主張請求權基礎、損害賠償計算、舉證責任分配    │
│ • 被告訴訟代理人 Agent  ：提出抗辯、免責條款、程序瑕疵與對抵抵銷      │
│ • 審判長法官 Agent      ：主持庭期、整理爭點、訊問雙方、頒布模擬判決  │
└────────────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────────┐
│ ⚖️ 刑事訴訟模式 (Criminal Courtroom Simulator)                          │
│                                                                        │
│ • 公訴檢察官 Agent      ：主張犯罪構成要件、舉證被告故意/過失、求處重刑 │
│ • 被告辯護律師 Agent    ：主張無罪推定、合理懷疑、證據無效與量刑事由   │
│ • 合議庭審判長 Agent    ：進行證據能力認定、法庭訊問、頒布模擬裁判     │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、四階段標準法庭程序協議（Courtroom SOP Protocol）

為避免多個 Agent 自由對話造成資訊混亂，系統採用標準刑事/民事訴訟法程序進程，確保輸出極具結構性與專業感：

```
[ 步驟 0：卷宗輸入與法規檢索 (Startup Guide RAG 引擎) ]
                        ↓
【第一階段：爭點整理與起訴/答辯聲明】
 • 檢察官/原告 Agent 陳述訴之聲明與起訴事實
 • 辯護人/被告 Agent 提出答辯要旨與法律依據
                        ↓
【第二階段：法庭訊問與證據攻防】
 • 法官 Agent 根據爭點向雙方提出尖銳訊問（例：「被告對此對話紀錄有何說明？」）
 • 雙方 Agent 進行證據能力（如違法採證）與證明力之交叉攻防
                        ↓
【第三階段：辯論終結與科刑/損害陳述】
 • 雙方 Agent 進行最終辯論總結與量刑/賠償主張
                        ↓
【第四階段：頒布 AI 模擬判決書與心證解析】
 • 法官 Agent 發布【模擬判決書主文與理由】
 • 產出【心證風險地圖】與【開庭建議補充之關鍵證據清單】
```

## 四、角色 Prompt 與 Skill 蒸餾規格

各 Agent 不使用通用提示詞，而是透過女媧 Skill 蒸餾技術賦予專業角色 DNA：

1. **法官 Agent (`taiwan-judge-perspective`)**：
   - **性格**：中立、客觀、嚴謹、對舉證責任劃分極度敏感。
   - **職責**：不偏袒任何一方，主導法庭程序，產出符合司法官風格之判決書主文與理由。
2. **公訴檢察官 Agent (`taiwan-prosecutor-perspective`)**：
   - **性格**：嚴苛、強調國家刑罰權、追查犯罪細節。
   - **職責**：精準套用刑法分則構成要件，打擊被告辯詞漏洞。
3. **辯護律師 / 原告律師 Agent (`taiwan-litigator-perspective`)**：
   - **性格**：維護當事人權益、善用無罪推定與條款解釋。
   - **職責**：採用《taiwan-legal-pleading》之正統法言法語進行抗辯。

## 五、UI / UX 設計概念：法庭即時文字直播 (Streaming Courtroom Log)

為了將原本需等待 1 分鐘的 Token 計算過程轉化為驚艷的使用者體驗：

- **介面風格**：採用高質感的「文字法庭現場直播（Live Courtroom Interface）」。
- **角色頭像與動態**：當「檢察官 Agent」發言時，介面突出檢察官卡片並以打字機效果串流輸出其論點；隨後自動切換至「辯護律師 Agent」回應。
- **即時爭點儀表板**：側邊欄動態更新「目前原告優勢 55% vs 被告優勢 45%」之即時評估。

## 六、結論與後續步驟

**建議開發順序**：
1. **MVP 階段**：優先完成民事模式之雙律師攻防 ＋ 法官判決（難度較低且符合大多數常見糾紛）。
2. **V1.5 階段**：導入刑事模式（檢察官 vs 辯護律師）與法庭即時文字直播 UI。
